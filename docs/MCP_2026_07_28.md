# MCP 2026-07-28 implementation contract

Maxey0 public targets MCP `2026-07-28` at the protocol boundary.

Implemented:
- Stateless Streamable HTTP request handling.
- No dependency on `initialize` / `initialized` or `Mcp-Session-Id` for the public protocol adapter.
- `MCP-Protocol-Version` request validation.
- `Mcp-Method` and `Mcp-Name` header routing for tools.
- `server/discover`.
- `tools/list`, `tools/call`, `resources/list`, `resources/read`, `prompts/list`.
- Cache hints (`ttlMs`, `cacheScope`) on list/read responses.
- Explicit application state above transport through SCW handles and Maxey0 stores.
- MCP Apps UI resource with `ui://` URI and `_meta.ui.resourceUri` tool linkage.

Not newly adopted:
- legacy HTTP+SSE transport
- new use of deprecated Roots, Sampling, or Logging
- Dynamic Client Registration as the forward authorization design

Extensions represented:
- MCP Apps
- MCP Tasks as an integration contract; long-running task state remains application-owned

Authorization deployment must validate issuer and bind credentials to the issuer. Production remote deployments should use the deployment's OAuth/OIDC/CIMD configuration rather than secrets in this repository.
