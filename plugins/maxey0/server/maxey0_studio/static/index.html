How this works

1

Concepts route

A task is scored against Maxey0's 16 concept tag vocabularies. The winning concepts decide which loops are even candidates.

2

Loops carry their partition

Each loop in the library was hardened by being built against a real ContextWindow: regions created, roles bound, every negative control actually attempted and actually refused.

3

SCWs enforce it

A bound role reads its own region and whatever it holds an explicit, expiring grant for. Anything else raises a refusal — that is the wall, and it is in the runtime, not in a prompt.

Concept → Skill → Agent → Dispatch

Creating an SCW here goes through the same hierarchy as everything else in Maxey0 — pick what's doing the work before there's anywhere for it to write. Every region created is real; every dispatch is a real write() against a real, enforced token budget.

Gate

Every tool call a delegated agent made, attributed to the SCW role it was bound to. This is the stream the runtime's own log cannot contain: it records what the host did to the window, while an agent dispatched as a subagent works in a context the window has no address for. The gate stands at the tool call, which is the one place that context has to ask for something.
